# Audit reference

Used by the [audit](../SKILL.md#audit) steps.
The [authoring gate](../SKILL.md#authoring-gate) and [retention bar](../SKILL.md#retention-bar) apply to every candidate.

## Junk patterns

Each pattern is a candidate unless the retention bar names an independent contract it guards:

- **Empty proof**: assertion-free probes, self-comparisons, identity copies, expected values generated by the subject.
- **Copied inventories**: manifests or export lists restated in the test, exact greps over source, imports, or strings.
- **Implementation coupling**: tests of a private predicate or call shape that duplicate boundary proof, and per-caller replays of a shared helper.
- **Test-only seams**: exports, globals, wrappers, or production paths whose only callers are tests.
- **Lying mocks**: mocks that implement the asserted behavior, or pretend two distinct APIs behave alike.
- **Fabricated fixtures**: receipts, admission, or callback ordering supplied by the fixture instead of the owner, and persistence asserted on a store path the code never writes.
- **Capability flags**: a flag asserted where the contract is actual delivery or acknowledgement.
- **Dead negatives**: a negative control that goes red on an unrelated guard, or a rejection the production code never reaches.
- **Lying names**: a name promising behavior the inputs and assertions never exercise.

Judge a test by its assertions, never by its name.

## Candidate evidence

Before marking a candidate, read:

- the full test, including its parameter tables
- the production owner, its entry point, callers, and callees
- sibling tests and any overlapping proof
- the test's git history
- the target repo's `AGENTS.md` or `CLAUDE.md`, root and scoped

For a claim that rests on a dependency, read the dependency's source or types.

Give each candidate one verdict:

- `Retain`: keep it; name the contract and the bug it catches.
- `Fix`: keep the contract, repair the assertion, such as a negative that stays green when only one of several items is missing.
- `Consolidate`: name the keeper that absorbs the assertion first: a sibling table row, a stronger boundary suite, or a shared owner.
- `Delete`: name the proof that remains, or show that no contract exists.

Record five evidence fields per candidate:

1. Exact name and location, and the failure it can detect.
2. Non-test callers of the production or support seam it covers.
3. The stronger proof that remains, or why none is needed.
4. Why it exists, from history, and what its removal unlocks.
5. Risk, and the focused command that validates the change.

Prefer a few high-confidence candidates over many weak ones.
Uncertainty is a reason to keep a test, never a reason to clean it up.
When discovery fans out to subagents, split by independent owner.
Readers in different lanes can meet the same test from different sides, such as a per-view replay that one lane sees as duplicate proof and another as wiring proof.
Compare their verdicts on shared tests, and mark a test both judged differently `disputed`.

## Validation

- Confirm each recorded mutation names the owner file, the change, and the assertion that went red, and that `git diff` on the owner shows only intended edits.
- Run the owner and sibling tests with the test command from the target repo's `AGENTS.md` or `CLAUDE.md`.
- For a removed source grep or plan assertion, run the executable or dry run it guarded.
- Find support files and exports the removed tests orphaned, with whatever dead-code tooling the repo has, and remove them.
- Run the repo's formatter and `git diff --check` on the changed paths, then the repo's green gate.
- Read `git diff --numstat` and split the line counts into production and test or support.
- Review the diff.
- Report every check you could not run.
